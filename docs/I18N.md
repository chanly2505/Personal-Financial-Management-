# Language and localization

The interface is in English. Everything is set up so Khmer (or another language) can be added without rewriting screens.

## What is in place

| Part | Where | Status |
|---|---|---|
| Message catalog | `src/i18n/messages/en.ts` | Shell and shared text: navigation labels and descriptions, buttons in shared components, loading/error/not-found text, skip link, account menu, Settings section names and choices. |
| Lookup | `src/i18n/index.ts` — `t("nav.dashboard.label")`, `t("common.couldNotLoadPageRef", { reference })` | Typed: a misspelled key is a compile error. `{placeholders}` are filled with already-formatted values. |
| Language list | `LOCALES = ["en"]`, `DEFAULT_LOCALE` | `<html lang>` comes from `DEFAULT_LOCALE`. |
| Amounts | `formatMoney` (`src/lib/money.ts`) | Per-currency decimals (USD 2, KHR 0); user's separators and symbol/code (PRD §6.13). |
| Dates | `src/lib/format/dates.ts` | User's date format; month and weekday names are English today. |
| Numbers | `formatInteger`, `formatPercent` (`src/lib/format/number.ts`) | User's separators. |

Feature screens (forms, pages, validation messages) still contain English text inline. They are written as complete sentences with values inserted at one point, which keeps them translatable; moving them into the catalog is mechanical and can happen screen by screen.

## Adding Khmer

1. Create `src/i18n/messages/km.ts` exporting `km: Messages` — TypeScript then lists every missing key.
2. Add `"km"` to `LOCALES` and the catalog map in `src/i18n/index.ts`.
3. Add a `locale` column to `users` and a "Language" choice in Settings → Region and display; pass the user's locale to `t()` (server) and through `FormatProvider` (client), and set `<html lang>` per request.
4. Month and weekday names: switch the `Intl.DateTimeFormat` locale in `src/lib/format/dates.ts` to `km` when the language is Khmer. Keep digits Latin unless users ask for Khmer digits (a separate number-format option).
5. Fonts: the Geist font has no Khmer glyphs; add a Khmer web font (e.g. Noto Sans Khmer) to the font stack before shipping Khmer text.
6. Move the remaining inline feature text into the catalog, starting with the most used screens (Transactions, Dashboard).

## Rules for new text

- Use whole sentences with placeholders (`"Spent {amount} of {limit}"`), never glue translated fragments together — word order differs between languages.
- Format numbers, money and dates first (`src/lib/format`), then insert them.
- Do not put text in images. Do not rely on text width: Khmer strings are often longer.
- Plain words for non-technical users; avoid jargon ("earmark" is explained where it appears).
